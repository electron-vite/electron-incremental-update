### Runtime flow

The generated reference above is the source of truth for signatures and option types. The usual runtime flow is:

1. Call `createElectronApp()` from the Electron entry process. It installs a verified pending asar, loads the configured main file, and initializes the updater.
2. Export `startupWithUpdater()` from the real main process when startup code needs the `Updater` instance.
3. Call `updater.checkForUpdates()`, then `updater.downloadUpdate()`, and finally `updater.quitAndInstall()` when an update is ready.
4. Use `autoUpdate(updater)` when the default check-download-install sequence is sufficient.

The updater emits `update-available`, `update-not-available`, `download-progress`, `update-downloaded`, `update-cancelled`, and `error`. Use the generated `Updater`, `UpdaterOption`, and error-code definitions above for exact payloads.

### Provider selection

All providers implement `IProvider`, which supplies update JSON, compressed asar downloads, decompression, version comparison, and signature verification. The generated section above contains the exact contract and option types.

- `GitHubProvider` reads `version.json` from a branch and downloads release assets from GitHub.
- `GitHubAtomProvider` discovers the latest release through GitHub's Atom feed.
- `GitHubApiProvider` uses the GitHub Releases API and supports an optional token.
- `LocalDevProvider` reads the same update files from disk for local testing; prefer `localDevUpdate: true` in the Vite plugin when possible.

GitHub providers accept `urlHandler` when requests must go through a mirror or custom gateway:

```ts
const provider = new GitHubProvider({
  user: 'your-github-user',
  repo: 'your-repo',
  urlHandler(url) {
    url.hostname = 'mirror.example.com'
    url.pathname = `https://github.com${url.pathname}`
    return url
  },
})
```

`LocalDevProvider` reads `{baseDir}/{versionPath}` and `{baseDir}/{name}-{version}.asar.br`. Its `chunkSize` and `chunkDelay` options only control simulated local download progress.

### Plugin Options

`electronWithUpdater()` accepts the process entries plus optional build and update settings. The generated `ElectronWithUpdaterOptions` reference below is the exact type definition; the common configuration shape is:

```ts
electronWithUpdater({
  entry: {
    files: './electron/entry.ts',
    asarOptions: {
      unpack: '**/*.node',
    },
  },
  main: { files: './electron/main.ts' },
  updater: {
    paths: {
      asarOutputPath: 'release/app.asar',
      compressedPath: 'release/app-1.0.0.asar.br',
    },
  },
})
```

`entry.asarOptions` is passed to `@electron/asar` when `app.asar` is created. Use `unpack` or `unpackDir` for native modules, `ordering` for deterministic file order, and the remaining `CreateOptions` fields for advanced packaging behavior. The same options are used by the local development update flow.
